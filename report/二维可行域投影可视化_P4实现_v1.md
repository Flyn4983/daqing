# 二维可行域投影可视化（P4 实现说明 v1）

> 日期：2026-11-22。范围：只读派生可视化，不改仿真内核 / NSGA-II / 权威数字。
> 交付物：仅本文（md），不生成 HTML。

## 1. 需求与定位

用户在 P3 之后追问："约束应该是实际的约束……应该能够在 GUI 中设定"。P3 已把三源约束做成 GUI 可录入、可校核、可硬筛选。本次补上最后一块可视化拼图：**把"哪些方案因约束被剔除"直观画出来**。

报告中的可行域是 `X={x∈R⁹×Z⁹ | 编制档位内，Σxᵢ≤上限，MTTR(x)≤MTTR_max，…}`（式3）。软件的对应表达是：

- **真实的离散可行域**：74 个已寻优 Pareto 方案，在 GUI 录入的资源/成本约束下，逐方案判定可行或超编。
- **二维投影**：任选两个维度（7 决策旋钮 + 6 结果指标）作 X/Y 轴，把 74 方案画成散点，叠加约束派生的硬边界与越界阴影。

## 2. 红线与诚实边界（必须说清）

| 红线 | 本次实现如何遵守 |
|---|---|
| 不改内核 | 只读 `pareto.json`；不写回、不重跑仿真/优化、不碰 `experiment/surrogate/FEATURES` |
| 权威数字不变 | 74 方案、knee(索引27)、R²=0.705、0.165/0.458/64% 全部不变；测试前后 `pareto.json` 的 md5 一致 |
| 不伪造控件 | 图是结果展示，不提供"拖动边界反推"的假交互；轴切换只重绘投影，不改变任何数据 |
| 明确非权威 | 图注写明：这是**离散方案投影**，不是连续可行域精确边界（后者需重跑内核寻优、会推翻权威数字）；文本类约束（上级命令/优先规则/抢修时限）在方案层校核，不形成数值轴 |

## 3. 数据链路

```
pareto.json（74方案权威，只读）
   │
   ├─ optimize_pareto.feasible_region(constraints, cost_ceiling, scenario)
   │      ├─ effective_bounds(constraints) → 7旋钮有效上界（约束.py）
   │      ├─ 逐方案判定 feasible / violations[]
   │      └─ 返回 axes(7决策+6指标) + points(74) + bounds + knee标记 + note
   │
   ├─ api.pareto_region(payload) —— 约束来源与 pareto_recommend 一致
   │      （payload.constraints 优先，其次最近录入且 constraints_configured 的 mission）
   │
   ├─ GET /api/support/pareto/region
   │
   └─ 前端 openRegionView() → renderRegion()
          ├─ X/Y 轴下拉（决策旋钮 / 结果指标两组 optgroup）
          ├─ SVG 散点：绿=可行 / 红=超约束 / 金色菱形=权威 knee
          ├─ 硬边界：X 轴受旋钮上界约束→竖虚线+右侧阴影；Y=cost 且设上限→横虚线+上方阴影
          ├─ 悬停 title 显示方案编号/两轴值/越界原因
          └─ 轴切换本地重绘（数据一次加载，零请求、零外网）
```

## 4. 入口与交互

- **入口一**：保障全过程 → 成本选优（Pareto 模态）→ 约束说明下方「◎ 查看二维可行域投影」按钮。
- **入口二**（数据面板）：研究细节 → 模型一「可行域 X 与三源约束」卡片（文字已说明落点；图从 Pareto 入口进入）。
- 打开后默认 X=`red_repair_teams`（受约束的决策旋钮）、Y=`cost`；可随时改轴。
- 关闭按钮复用通用 `.sf-modal-x` 委托，无需额外绑定。

## 6. 实测数据

### 后端（`.venv/Scripts/python.exe`）
- 无约束：74 总 / 74 可行 / 0 剔除（**零漂移**，与旧版行为一致）。
- `repair_veh_cap=2`：剔除 8 个（`red_repair_teams>2` 的方案），`bounds.red_repair_teams=2`。
- `cost_ceiling=0.3`：剔除 30 个，可行方案 `cost` 均 ≤0.3。
- knee 标记唯一且索引=27，与 `pareto.json tags.knee` 一致。
- 测试前后 `pareto.json` 的 md5 完全相同。

### 单测
`test_support_pareto.py` + `test_constraints.py`：**45 passed**。
全套 support + 约束回归：**120 passed**（上次 111，本次 +9）。

### 浏览器（Playwright headless，8848 服务）
14 项检查全 True，0 控制台错误：
- 默认场景：SVG 渲染 73 绿点 + 1 knee 菱形、轴切换正常、modal 开关正常；无虚线（因默认约束不超编，正确）。
- 紧约束场景（保存 `repair_veh_cap=2`）：渲染 1 条竖虚线边界 + **8 个红点** + "剔除"提示——与后端剔除数完全一致，证明"约束边界可视化"真实生效。

## 7. 已知边界

1. 二维投影只能展示所选两维；被约束但不在轴上（如抢修时限、上级命令）的约束不会在图上形成边界，其判定在方案层校核表中体现。
2. X/Y 轴取的是 74 方案已有字段，未新增任何仿真指标。
3. 图是"结果侧投影"，回答"哪些方案可行"，不回答"如何调整约束让更多方案可行"——后者是寻优内核职责，按红线不在此实现。

## 8. 与 P3 的关系

P3 解决"约束能不能设、设了有没有效"，P4 解决"约束效果能不能看见"。两者共同守住同一红线：约束在**方案层 + 选优层**生效，不注入寻优内核，权威数字与寻优结果完全不动。
