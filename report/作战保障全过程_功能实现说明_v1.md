# 作战保障全过程功能实现说明 v1

> 对应需求：在尽量不大改现有内核和整体架构的前提下，把前面《与合成旅保障对齐_需求与改造分析_v1.md》
> 列出的全部功能需求落地；界面合理布局、信息层级清晰；完整体现作战保障全过程及各节点式环节的
> 衔接关系与状态变化。目标部署环境：Ubuntu ARM / 128GB 统一内存 / qwen3.8-27B。

---

## 1. 实现原则与改造边界

| 原则 | 落地方式 |
|---|---|
| **不改仿真内核** | 全部新增逻辑在 `src/brigsim/support/`；仅复用现有 MesaKernel、`run_replications`、`four_rates` |
| **不改整体架构** | `server.py` 只增加 11 行路由分派；前端只新增独立 JS/CSS，不修改已有 JS |
| **权威数字冻结** | 油料/日常业务/通用消耗品只在方案层建模，不进内核；R²=0.705、加速比≈38 万倍、Pareto 74 等不变 |
| **数字不由模型编造** | 数值槽位确定性填充；LLM 只写叙述；响应含阿拉伯数字即判无效并回退 |
| **离线可用** | 模型走 127.0.0.1 回环；模型未就绪自动降级模板叙述，推演与清单不受影响 |

## 2. 全过程节点式流程（8 节点状态机）

顶栏「保障全过程」打开全屏抽屉，顶部横排 8 个节点，节点间以箭头连接：

```
① 任务与资源录入 → ② 编成校验与配置生成 → ③ 多次对抗推演 → ④ 战损清单生成
→ ⑤ 战损率等指标派生 → ⑥ 保障方案生成 → ⑦ 数字一致性复核 → ⑧ 清单/方案导出
```

每个节点有 5 种状态，由真实数据驱动（非静态装饰）：

| 状态 | 视觉 | 触发条件 |
|---|---|---|
| 未开始 | 灰点 | 初始 |
| 就绪 | 蓝点 | 前置节点完成 |
| 进行中 | 黄点脉冲 | API 调用/后台推演中 |
| 完成 | 绿点+绿框 | 数据落盘且校验通过 |
| 异常 | 红点 | 校验失败或请求出错 |

点击节点可跳转到对应栏（①②→左栏，③~⑤→中栏，⑥~⑧→右栏）。

## 3. 输入能力（左栏）

以资源目录（`/api/support/catalog`）为唯一数据源动态渲染 7 组表单：

| 组 | 内容 | 数量 |
|---|---|---|
| 任务与推演参数 | 名称、类型、基础工况、时长、MC 次数、随机种子 | 6 项 |
| 装备编成 | 23 类地面平台 + 3 类空中架次，按 7 个力量群折叠 | 26 类 |
| 弹药储备 | 穿甲弹/机关炮弹/反坦克导弹/间瞄榴弹/防空导弹/地雷 | 6 类 |
| 油料与油脂 | 柴油/航空煤油/汽油/润滑油脂（储备、前送） | 4 类 |
| 保障车辆 | 抢修车/抢救车/器材车/弹药车/油罐车 | 5 类 |
| 器材与消耗品 | 4 类可修部件 + 给养/卫勤/工程器材，三级储备 | 7 类 |
| 日常业务要素 | 战备等级/装备值勤/训练计划/请领审批/维护保养 | 5 类 |

共 128 个输入控件，字号 10~11px，编成按群折叠，一屏可总览。
保存后映射到现有 7 个保障旋钮 + 任务参数（复用 `to_run_config()`），**不改内核**。

## 4. 输出能力（中栏 + 右栏）

### 4.1 多次推演与战损清单

- 后台线程跑 N 次 MC 复制（默认 8，可调 1~60），1.2 秒轮询进度条。
- 从事件快照取每个单位**终态**，生成逐件战损清单，字段含：
  编号 / tick / 阵营 / 单位 ID / 平台类型 / 类别 / 建制 / 损伤等级(M/F/K) /
  损伤部位 / 致损原因 / 致损武器 / 处置方式 / 修复状态 / 预计修复时长 / 坐标。
- 落盘 `outputs/support/loss/loss_<id>.json` + `.csv`（UTF-8 BOM，可直接上报）。
- 多维汇总：按等级、处置、类别、平台、阵营。

### 4.2 战损率等指标（由清单派生，与内核对账）

| 指标 | 口径 | 说明 |
|---|---|---|
| 战损率 | K 级战毁数 / 我方参战数 | 与内核 `1-alive_n/n` **完全等价**，对账容差 1e-6 |
| 战斗损伤率 | (K+M+F) / 我方参战数 | 新增单列，不改变权威战损率 |
| 完好率 | (存活且未受损且不在修) / 我方参战数 | 对账容差 1e-3 |
| 修复率 | 已修复 / (已修复+在修) | 由清单 repair_status 派生 |

**关键口径修正（实测踩坑）**：快照混含红蓝双方（14 红 + 9 蓝）。若用全体 23 做分母，
清单会算出 0.435，而内核战损率是 2/14=0.143 —— 对账失败。现已按 `side` 过滤：
清单保留双方记录（蓝方属战果），但四率派生只用红方。修复后实测 diff=0.0。
对账基准取**清单所属的那次复制**（`rows[0]`），而不是 N 次均值，避免口径错配。

### 4.3 保障方案（十章制式结构）

模板位于 `templates/support/support_plan_v1.md`，首次运行自动生成，可直接替换为正式模板
（保留 `{{slot_id}}` 即可，75 个槽位字典见 `/api/support/catalog`）。

十章结构：情况判断 → 保障任务与决心 → 战损预计与需求测算 → 力量编组与部署 →
抢救抢修计划 → 器材弹药油料补给计划 → 装备后送计划 → 防卫通信运输 →
实施步骤与报告时机 → 附表（战损表/器材表/编成表/部署图/时序表）。

**数字与文字分离**：
- 43 个数值槽位全部来自清单/录入（确定性填充）；
- 31 个叙述槽位由本地 qwen3.8-27B 按 4 段生成，系统提示词禁止输出任何阿拉伯数字；
- 响应含数字或 JSON 非法即逐段回退模板默认文字；
- 生成后扫描未替换槽位、叙述编造数字、关键数字缺失，任一命中即判复核失败（界面显示红色）。

## 6. 界面操作动线（约 30 秒）

1. 顶栏点「保障全过程」→ 抽屉展开，8 节点流程条 + 三栏。
2. 左栏已预填默认编成；按需修改数量、选工况、设时长/次数 → 点「保存录入并校验」→ 节点 ①② 变绿。
3. 中栏设推演次数 → 点「开始多次推演」→ 进度条推进 → 清单表格与 6 张指标卡出现；
   对账条应为绿色（若红色说明清单与内核数字不一致，需排查）。
4. 右栏选模板、勾选本地大模型 → 点「生成保障方案」→ 十章方案渲染；
   复核条为绿色；落款显示实际模型名与降级段数。
5. 点「↓清单」「↓方案」分别导出 CSV/Markdown。

## 9. 已知限制与待确认

1. **模型 ID**：`Qwen3.8-27B` 按用户给定名称配置；实际部署请以 `/v1/models` 返回 ID 为准修改 `llm_config.json`，否则 auto 模式会降级为模板叙述（推演与清单不受影响）。
2. **模板尚未替换为制式件**：当前十章模板是按条令通行结构自拟的样例；用户提供正式模板后，按槽位 ID 对齐即可替换（未知槽位会报错，不会静默漏填）。
3. **油料/日常业务不进内核**：只在方案层测算；若需油料影响装备机动，属于内核改造，须重新标定全部权威数字。
4. **清单来源**：有事件流时为逐件明细；无事件流（仅有 MC 汇总）时按类别估算并标注"估"，不伪造逐件记录。
5. **并发上限**：最多 8 个推演任务，超出后自动回收已完成的最旧任务。
