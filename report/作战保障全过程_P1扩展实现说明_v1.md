## 2. 关键实现约定

### 2.1 数字与文字分离红线（P1-2）

`apply_overrides()` 强制：
- 只接受 `SLOT_DICT[slot].source == "llm"` 的槽位；任何数值槽位（source 为 mission/loss/rates/generated/decision/scenario）一律拒绝；
- 覆写文字内出现阿拉伯数字即拒绝（防人工引入与清单冲突的数字）；
- 覆写后重新执行 `fill_template` + `validate_document` + `build_provenance`；
- 另存为新方案（`based_on` 指向原方案），**不覆盖原稿**，`narrative_locked=True` 标记锁定。

### 2.2 LLM 参数缺省零漂移（P1-3）

`generate_narratives` 新增参数全部带默认值：
- `temperature=0.25`、`max_tokens=900`、`retries=1`、`group_size=4`（等于原分段数）；
- 不传参数时行为与原实现完全相同；
- 降级（无 client / use_llm=False）路径的 `_meta` 也带 `params` 字段，结构一致。

### 2.3 3D 定位低耦合（P1-4）

不侵入 3D 视图与 rerun 回放：清单定位按钮做两件事——
1. 显示定位卡（单位 ID、实体路径 `world/units/{uid}`、装备、等级/处置、位置/tick）；
2. 通过 `window.dispatchEvent(new CustomEvent('brigsim:focus-unit', {detail}))` 广播，供 3D 视图**可选**订阅做镜头联动。

这是诚实的边界：当前回放按 tick 逐帧推演、静态 rrd 不支持直接跳转聚焦，故定位卡提供实体路径与数据，真正的镜头联动留给 3D 视图按需订阅。

### 2.4 作业档案数据契约（P1-8）

`GET /api/support/archive` 返回：

```json
{
  "missions": [{"id":"...","task_name":"...","scenario":"...","saved_at":"...","file":"..."}],
  "losses":  [{"id":"...","task_name":"...","attrition":0.071,"n_items":11,"base_seed":20261122,...}],
  "plans":   [{"id":"...","attrition":0.071,"validation_passed":true,...}],
  "counts":  {"missions":15,"losses":10,"plans":10}
}
```

档案为**落盘持久档案**（扫 `outputs/support/{missions,loss,plans}/`），非会话内内存列表——对应《优化建议》§7 待确认问题 4 的推荐形态。

## 5. 已知边界与待确认

1. **3D 镜头联动未实装**：P1-4 目前是"定位卡 + 事件广播"，未做 rerun 镜头自动飞到该单位。原因：静态 rrd 按 tick 播放、rerun web viewer 无简单 entity focus API；若确需联动，需在 3D 视图订阅 `brigsim:focus-unit` 事件并驱动 replay 时间轴跳转到该单位 tick（可做，属增量增强）。
2. **档案无版本 diff / 签批流**：P1-8 只做列表与关键指标汇总，P2 的方案版本对比（P2-2）、签批工作流（P2-3）未做。
3. **模板替换需槽位 ID 对齐**：上传的正式模板必须用 `{{slot_id}}` 标记且 ID 在 77 槽位字典内；映射表会标出未知槽位与未使用槽位供核对。
4. **导航未重构**：按规划 §6 属第三批"视需要"；当前 P1 功能以折叠面板/模态承载，未影响 8 节点流程与三栏主结构。若后续做 P2（批量工况对比、方案 diff、数据字典页），建议按 §4.3 重构为四区分层导航。
