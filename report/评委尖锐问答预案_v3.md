# 评委尖锐问答预案（v3 · 报告细节可追溯专项）

> 配套：「研究细节」面板（顶栏按钮）+ `report/报告细节与软件对照_v3.md`。
> 原则：**不吹、不躲、给证据**。凡面板标🟢的数字，当场可点开看实算；凡标🟡的，如实说是报告结论、原始输出未落盘。

## 一、针对"报告写的软件里到底有没有"

**Q1：你们报告图8写"9维决策+9维固定条件+三源约束"，软件里在哪？**
> 分三步演示：
> 1. 点顶栏「研究细节 → 模型一」，展示可行域 X 的四类不等式与 A/B/C/D 三源映射；
> 2. 点「方案设计」页，指"表示—映射—反演—复验"四子链与四层架构；
> 3. 打开「▶实时推演」配置弹窗，指 ③保障资源旋钮（决策维）、④情景因子（固定条件）。
> 诚实补充："图8是设计层，软件是可运行实现层——优化器里实际放7个可调旋钮+3个情景因子，另2维作为固定条件；三源分类是我们界定可行域的方法学，落到软件就是成本权重、档位边界和终审守卫。面板里都如实标注了。"（不宣称逐条实现9维）

**Q2：η=0.488→0.491 这个数是不是你们凑出来的？**
> 点「研究细节 → 模型一」，现场指四方案 η 分解表和公式 W=[0.35,0.25,0.25,0.15]，说明"这是从 pareto.json 的完好率/战损率/修复率/故障率按式(1)现算的，权重就是报告图13同款"。再点主屏金框 η 卡，两处口径一致。可当场报出基线分项 0.139/0.179/0.072/−0.051。

**Q3：±30%权重扰动200组、前沿69~73号——数据在哪？**
> 「研究细节 → 模型一」右上角卡片显示"5个，69~73号，每组≥195次"。说明这是用 numpy default_rng(42) 对 200 组扰动权重重算 75 个方案排序得到的，脚本 `tools/build_verification_data.py` 可现场打开。

**Q4：74个解"三源约束零越界"怎么证明？**
> 「研究细节 → 模型一」右下卡显示"0 项越界 / 74解 / 7维编制档位"，说明按 FEATURES 的 lo/hi 边界逐维核对。可打开 pareto.json 任取一方案核对档位。

## 二、针对模型二/三/四的验证

**Q5：模型二的 MTTR≈MTTR₀·exp(Q/c) 在软件里能算吗？**
> 「研究细节 → 模型二」展示式(6)和抢修组6/10/14的 MTTR 相对值（1.00/0.72/0.69），如实说明"这三个是报告正文的重跑结论，原始输出未落盘，面板标了🟡报告正文；软件用四率代理和 Pareto 间接体现该机理，可在智能参谋问'抢修组从6加到14'看边际递减"。（不谎称软件实时算 MTTR）

**Q6：R²=0.705 是真算的还是写的？**
> 「研究细节 → 模型三」九项 R² 明细表，数据来自 surrogate.json，点主屏"四率代理预测"面板可看九项散点。现场报出范围 0.341~0.882、均值0.705、n_train=192/n_holdout=48。

**Q7：130/200 和 Wilson 区间 [0.582,0.713] 怎么来的？**
> 「研究细节 → 模型四」：130/200 来自 distribution.json（点主屏 MC分布卡可看直方图）；Wilson 区间由 130/200 用 z=1.96 现算得 0.5816~0.7127，与报告 [0.582,0.713] 吻合。K1=48/K2=200 是报告正文口径（标🟡），说明"按置信半宽反算样本量，先定样本再算半宽"。

**Q8：消融实验8个候选2个掉线有证据吗？**
> 如实说明："这是报告表3的结论，原始8个候选明细未落盘，面板标了🟡；软件用三档方案+复验过闸间接体现——代理直接采信会出现端点偏差，守卫就是为避免这个。"（诚实，不被追问穿帮）

## 三、针对数据口径冲突（最容易被抓）

**Q9：为什么方案卡 success 是 0.7104，报告写 0.650？是不是数据造假？**
> 这是**口径不同，两者都对**：0.7104 是代理模型秒级预测值（knee 方案在代理上的输出），0.650 是 200 次蒙特卡洛终审的统计达标率（130/200）。方案卡已加口径说明行。面板「模型一/模型四」分别标注来源。强调"我们从一开始就把两个口径写明，没有混淆"。

**Q10：报告里 η 分解有两套权重（0.488/0.420/0.491/0.550 vs 0.488/0.399/0.491/0.596）？**
> 面板统一采用**报告图13生成脚本 make_verify_figs.py 同款口径** W=[0.35,0.25,0.25,0.15]（现算得 0.488/0.399/0.491/0.596），与报告配图完全一致；主屏金框 η 卡用反推权重仅复现 0.488→0.491 两端点。两套端点一致，面板里已注明口径来源。

## 四、针对"现场能不能真跑"

**Q11：这些面板数字是写死的吗？换台电脑还是这些数吗？**
> 不是写死。🟢数字全部来自 `/data/*.json` 并由 `tools/build_verification_data.py` 现算；换机只要数据文件在，面板读的就是那份数据。🟡数字是报告结论，面板如实标注来源——"我们连哪些是实算、哪些是报告结论都分色标出来了，这本身就是可信度"。

**Q12：断网能用吗？大模型没起怎么办？**
> 全流程走 127.0.0.1 回环，零外网。大模型未就绪时自动降级内置模板，智能参谋角标显示"○内置模板"；起了则显示"●本地大模型真实生成"。数字在任何情况下都由仿真内核保证，不依赖模型。
